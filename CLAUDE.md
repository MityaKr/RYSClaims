# RYSClaims

Земля команд для семьи RYS: приват, лимиты, прогрузка, защита. Заменяет FTB Chunks (вместе с RYSMap). modid `rysclaims`, пакет `works.repka.rysclaims`, NeoForge 1.21.1. Автор Дмитрий (MityaYS, RepkaWorks).

План и макеты: `../../_shared/_audit/map/plan.md` (разделы 6, 9.2, 10.5, 11, 12, этапы 13.4), факты разведки `R0-facts.md`, макеты `img/30`–`53`. Вид и тон семьи: `../RYSCore/CLAUDE.md`, раздел «Карта, приват и переезд (1.11)».

## Как работать с автором

* Общаться только по-русски. Прогресс списком, сделанное помечать ✅.
* Механики не выдумывать: CFR, исходники `../RYScope/research/mcsrc`, логи, тест в новом мире.
* Файлы не удалять, ненужное в `_stale`.
* Тексты для игроков черновые (`lang/ru_ru.json`), автор смотрит их до выпуска.

## Устройство

* `data/` без игры (кроме NBT): `ClaimData` вся земля в памяти и формат `rysclaims.dat`, `Claim`, `TeamLand` (добавки, права, переключатели, доверенные), `Rights`, `Limits`, `PlayerBonus`, `Settings` (снимок настроек), `Plots` (участки на лету), `Chunks` (упаковка как `ChunkPos.asLong`). `ClaimSavedData` это только обёртка `SavedData`.
* `server/ClaimService`: вся логика без игры (занять, освободить с отсчётом, оставить, прогрузить, права, машины, события команд). Измерение в нём строка id, время из `clock`. Клиенту не верим.
* `server/Loader` + `LoadPlan`: билеты `TicketController` `rysclaims:land` (сущность = UUID команды, ticking). Проверка при загрузке мира снимает лишние, `sync` раз в 10 секунд и по событиям сверяет поставленное с нужным.
* `server/ClaimsServer`: жизнь на сервере (ServerStarting, высокий приоритет, раньше переезда ядра в ServerStarted), тик, вход.
* `server/Protection`: защита событиями NeoForge, первым делом дешёвый выход (в измерении нет земли). Фейковый игрок судится `machineNames`, профилем и «Машины снаружи», его позиции не верим (R0, пункт 0.1). Порча блоков мобами судится только у монстров (`Enemy`): иначе на базе встали бы овцы, жители и големы.
* `server/Borders`: жидкость, огонь, молния через границу (зовут перехваты `mixin/`); сначала номера чанков, поиск только на границе.
* `server/DenyLog`: журнал отказов в памяти и файлах `world/rysclaims/log`, запись раз в минуту в своём потоке. `net/ClaimsNet`: пакет `Denied` (необязательный канал), `client/DenyFeedback` показывает причину.
* `mixin/`: перехваты игры там, где событий нет (`rysclaims.mixins.json`, `defaultRequire = 1`: сломанный перехват роняет GameTest).
* `mixin/compat`: перехваты машин чужих модов (`@Pseudo`, строки целей, необязательный набор `rysclaims.compat.mixins.json`, `CompatPlugin` включает класс по префиксу имени, только если мод загружен). Сигнатуры сверены `javap` с jar сервера RepYS. `server/Machines`: решение по месту блок-сущности и журнал.
* `compat/sable/SableLand`: позиция участка Sable в мировую и дом постройки (компаньон отражением, сначала проверка сетки `Chunks.sablePlot`); `SableAssembly` + `mixin/compat/SableAssemblyMixin`: фильтр блоков сборки и запись дома в `ClaimData.homes`.
* `server/Commands`: `/claims`; `server/ServerConfig`: `world/serverconfig/rysclaims-server.toml`.
* `api/ClaimsApiImpl`: контракт ядра `claims.ClaimsApi`.
* `migrate/FtbWorld`, `FtbSettings`: чтение файлов FTB через `migrate.Snbt` ядра (своего читателя нет). `FtbClaims` считает перенос без игры, `ClaimsStep` это шаг `claims` ядра (порядок 30): кладёт базу одним сохранением, потом билеты; откат отказывает, если после переезда землю правили (счётчик `edits`).
* Права управления землёй (`rysclaims:claim`, `force`, `rights`) регистрируются в таблице прав RYSTeams (`TeamsApi.registerPermission`), второй таблицы ролей нет.

## Принятые решения

* Режим личных добавок `sum` складывает только добавки, а не полные лимиты, как FTB; `largest`, `owner`, `average` совпадают с FTB.
* Добавка за участника считается за каждого сверх первого.
* Лидеру своей земли можно всё; права монотонны: «все» ⊇ «союзники» ⊇ «команда»; гость в 0.1 получает столбец «Союзники».
* В `rights` хранятся только четыре действия доступа; права управления живут в RYSTeams (план, решение 18).
* `/claims admin bonus <игрок>` (личная добавка) добавлен сверх списка плана: без него личную добавку не выдать без квеста.
* `/claims loadmode online|always`: выбор команды в пределах `maxForceLoadMode` сервера (в плане это окно `42`).
* Переезд: «файла настроек ещё нет» из плана проверяется как «все значения по умолчанию» (`ServerConfig.untouched`): игра создаёт файл раньше шага.
* Команда FTB без пары остаётся за старым UUID, а её участники (`legacy.members`) остаются «своими» на её земле: иначе перенос отнял бы у них доступ. Управлять такой землёй может только оператор.
* Серверная команда FTB тоже остаётся за своим UUID с пометкой `ftb-server`; своей команды «Сервер» в 0.0.x нет.
* Земля FTB в измерении, где у нас приват закрыт (`neovitae:dungeon`), переносится: её не отнимаем, в отчёте строка.
* Жидкость FTB в RepYS через границу текла: перенос это сохраняет (`fluidsAcrossBorders = true`). Огонь FTB тоже не защищал, но у нас он не переходит и после переноса (план, таблица настроек).
* Снаряд Create Big Cannons без хозяина и без центра взрыва: землю команды не портит, кроме `ownerlessExplosions = always`.
* Машине с известным местом (блок-сущность) своя земля доступна на любом расстоянии: обе точки на земле одной команды, а «два чанка» плана защищали от недостоверной позиции фейкового игрока.
* Перехват машины отменяет метод работы в начале, а не вызов `setBlock`, если дроп собирается или предмет тратится раньше: иначе был бы дюп. Где так нельзя (насос Oritech), машина не покрыта и записана в CHANGELOG.

## Проверка

```bash
gradlew test                 # JUnit без игры: хранилище, лимиты, сервис, билеты, файлы FTB
gradlew runGameTestServer    # тестовый сервер без окна, куча 2 ГБ: команды, билеты, выход игрока, шаг переезда
```

* Настоящие файлы FTB RepYS берутся из `../../_shared/_saved/fixtures/ftb-2026-11-18` (вне git, свойство `-Pfixtures=`); без папки тест пропускается. В git лежат заготовки того же формата `src/test/resources/ftb`.
* GameTest живут в `src/gametest` и в jar не попадают. Перед запуском игры проверить свободную память. Перед каждым запуском старый мир `run-server/world` переносить в `_stale` (шаг переезда в нём уже сделан).
* `gradlew runGameTestServer -PcompatMods=C:/Projects/RepYS-Server/mods` подкладывает Cyclic и flib (только чтение): так проверяется весь путь перехватов `mixin/compat`.
* Чанки тестов не тикают: поршень, молнию, огонь, ломатель Cyclic тест тикает сам (`triggerEvent`, `tick`), воду проверяет через `canSpreadTo`. Билет `setChunkForced` в далёкой земле запускает генерацию сотен чанков, не ставить. Тест кончается через `done(h)` (успех через 3 тика): иначе временные билеты синхронной загрузки мешают остановке.
* Остановка сервера GameTest иногда бесконечно крутится в выгрузке чанков (рабочие потоки стоят): сторож в `build.gradle` снимает процесс этого запуска через 30 секунд после строки итога, вердикт берётся из лога.
* Сборка требует соседний `../RYSCore` с выполненным `gradlew publish` (ядро 1.11.0).
